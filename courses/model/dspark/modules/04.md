## [m4-deepspec] DeepSpec 仓库

::: concept
title: DeepSpec 是一个全栈训练与评估代码库
why: DSpark 不仅开源了权重，还开源了训练 draft 模型的完整流程。

DeepSpec 仓库（`deepseek-ai/DeepSpec`）包含三种投机解码算法实现、训练脚本、配置和 9 个离线 benchmark。
:::

| 组件 | 内容 | 用途 |
|------|------|------|
| 算法实现 | DSpark、DFlash、Eagle3 | 对比与复现投机解码方法 |
| 训练脚本 | 数据准备、多 GPU 训练、评估 | 从头训练或继续训练 draft 模块 |
| 配置文件 | `config/dspark/dspark_qwen3_4b.py` 等 | 定义模型、训练超参与数据路径 |
| 离线 benchmark | GSM8K、MATH、AIME25、HumanEval、MBPP、LiveCodeBench、MT-Bench、Alpaca、Arena-Hard-v2 | 评估 accepted length 与生成质量 |

延伸阅读：
- [DeepSpec GitHub 仓库](https://github.com/deepseek-ai/DeepSpec)
- [HuggingFace DeepSeek-V4-Pro-DSpark 权重](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro-DSpark)

::: concept
title: 冻结目标模型，复用 embedding 与输出头
why: 不需要重新训练大模型，只需要训练一个外挂 draft 模块。

DSpark 的训练只更新 draft 模块参数：

- 目标模型（如 DeepSeek-V4）权重完全冻结。
- Draft backbone、sequential head、confidence head 从零或 warmup 开始训练。
- Embedding 层和输出头复用目标模型，保证 draft 与 target 的 token 分布对齐。

这样做的好处是训练成本低，且不会破坏原模型的输出分布。
:::

| 阶段 | 主要工作 | 输入 | 输出 | 主要成本 |
|------|----------|------|------|----------|
| 数据准备 | 收集并切分训练语料 | 原始文本 / 对话数据 | 训练序列 | 数据清洗与存储 |
| Target cache | 用冻结目标模型前向训练数据 | 训练序列 | 中间层特征与输出分布 | 大量存储空间（Qwen3-4B 约 38 TB） |
| Draft 训练 | 训练 backbone、sequential head、confidence head | Target cache + 训练序列 | DSpark checkpoint | 8 GPU 训练时间 |
| 评估 | 在 9 个 benchmark 上测 accepted length | 训练好的 checkpoint | 评估报告 | 推理算力 |

::: evidence
claim: DSpark 的训练配置默认单节点 8 GPU，Qwen3-4B 设置下 target cache 约 38 TB。
source: [MarkTechPost: DeepSeek Releases DSpark](https://www.marktechpost.com/2026/06/27/deepseek-releases-dspark-a-speculative-decoding-framework-that-accelerates-deepseek-v4-per-user-generation-60-85-over-mtp-1/)
status: verified
basis: 报道明确提到默认 8 GPU 配置与约 38 TB target cache（Qwen3-4B 设置）。
:::

## [m4-checkpoints] 已发布的 Checkpoint

| Checkpoint | 基础模型 | 包含内容 | 适用场景 |
|------------|----------|----------|----------|
| `deepseek-ai/DeepSeek-V4-Pro-DSpark` | DeepSeek-V4-Pro | 目标模型 + 训练好的 draft 模块 | 追求最高质量的生产服务 |
| `deepseek-ai/DeepSeek-V4-Flash-DSpark` | DeepSeek-V4-Flash | 目标模型 + 训练好的 draft 模块 | 成本敏感、延迟敏感的生产服务 |

它们不是新训练的目标模型，而是原 V4 checkpoint 加上训练好的 draft 模块。推理框架可以直接加载并启用投机解码。

## [m4-deployment] 生产部署

::: concept
title: vLLM / SGLang 服务方式
why: 主流开源推理引擎已支持或正在集成 DSpark。

示例启动命令：

```bash
# vLLM
vllm serve "deepseek-ai/DeepSeek-V4-Pro-DSpark"

# SGLang
python3 -m sglang.launch_server \
  --model-path "deepseek-ai/DeepSeek-V4-Pro-DSpark"
```

实际部署时还需要配置 speculative decoding 参数，如 draft 长度、验证 batch size、置信度阈值等。由于集成状态变化较快，具体参数名和默认值建议查阅对应引擎的最新文档或 issue。

延伸阅读：
- [vLLM Issue: Support DSpark for DeepSeek V4](https://github.com/vllm-project/vllm/issues/46910)
- [vLLM Issue: DSpark performance](https://github.com/vllm-project/vllm/issues/46931)
:::

::: evidence
claim: vLLM/SGLang 对 DSpark 的支持仍在快速迭代中，命令和参数可能随版本变化。
source: [vLLM Issue #46910](https://github.com/vllm-project/vllm/issues/46910)

- 准备 target cache
- 训练 draft 模块
- 在线服务加载 DSpark checkpoint

1. 大量存储空间
2. 8 GPU 训练时间
3. 几乎零额外训练成本

## [m4-summary] 本章小结

- DeepSpec 提供 DSpark / DFlash / Eagle3 的全栈训练与评估代码。
- DSpark 冻结目标模型，只训练 draft 模块，训练成本低。
- 目标缓存可能很大，但生产 checkpoint 可以直接加载使用。
- vLLM、SGLang 等引擎正在集成，部署前需核对最新文档。
