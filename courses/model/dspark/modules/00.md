## [m0-why-history] 为什么要先读历史

::: concept
title: DSpark 不是从石头里蹦出来的
why: 只有知道早期方法解决了什么、卡在哪里，才能理解 DSpark 的改进为什么重要。

投机解码在 2022–2023 年被两组研究者几乎同时提出：

- **Leviathan, Kalman, Matias（Google Research）** 在 2022 年 11 月发布 *Fast Inference from Transformers via Speculative Decoding*， coined the term "speculative decoding"。
- **Chen 等（DeepMind）** 在 2023 年 2 月发布 *Accelerating Large Language Model Decoding with Speculative Sampling*，用几乎相同的思想独立复现了加速效果。

两篇论文都回答了一个核心问题：**能不能让小模型先猜一串 token，再让大模型一次性验证，同时保证输出分布不变？** 答案是肯定的，但早期论文只给出了基础框架，很多工程问题——draft 怎么训练、接受率怎么提升、高并发下怎么调度——留给了后续工作，包括 DSpark。

延伸阅读：
- [Fast Inference from Transformers via Speculative Decoding](https://arxiv.org/abs/2211.17192)
- [Accelerating Large Language Model Decoding with Speculative Sampling](https://arxiv.org/abs/2302.01318)
:::

## [m0-problem] 2022 年之前的瓶颈

::: concept
title: 自回归解码的每一步都很贵
why: 大模型生成一个 token 的成本几乎和生成多个 token 一样，但用户每次只看一个。

在 Transformer 出现之前，神经语言模型已经面临同样的问题：生成文本时只能一个词一个词地出。Transformer 把单次 forward 的并行度做到极致，但 decode 阶段仍然被迫串行——因为第 $t$ 个 token 的输入里必须包含第 $t-1$ 个 token。

Chen et al. 在论文里指出，小 batch 下 Transformer 采样主要被三样东西拖慢：

1. **Linear Layers**：小 batch 时矩阵乘法变成 memory-bound，每次 forward 算力浪费严重。
2. **Attention Mechanism**：KV cache 很大，但大小不随一次验证的 token 数变化。
3. **All-reduces**：模型大到要分布式部署时，每层的通信开销几乎和单次采样一样。

因此，**并行评分 $K$ 个 token 的延迟，和采样 1 个 token 的延迟几乎相同**。这是投机解码能工作的硬件前提。
:::

::: qa
question: 为什么 Transformer 把单次 forward 的并行度做到极致，decode 阶段仍然只能一个词一个词地出？
section_id: m0-problem
answer: |
  这是两个完全不同的“并行”层次，混在一起很容易困惑。

  **层次 1：单次 forward 内部的并行**
  Transformer 的 self-attention 和 FFN 都可以写成矩阵乘法。输入一句话有 $N$ 个 token 时，这 $N$ 个 token 的表示可以**同时**算出来——不需要像 RNN 那样等第 1 个算完再算第 2 个。所以训练时 batch 一大，GPU 利用率很高。

  **层次 2：decode 生成时的串行**
  但生成文本是另一回事：你想生成第 $t$ 个 token，必须先知道第 $t-1$ 个 token 是什么，因为它要作为输入的一部分。这个依赖是**任务本身**带来的，不是模型结构能消除的。

  打个比方：
  - forward 内部并行 = 一次批改全班 50 份卷子，可以 50 份同时看。
  - decode 串行 = 写一部长篇小说，第 100 章怎么写取决于第 99 章写了什么，没法提前写。

  所以 Transformer 解决的是“同时看/算很多 token”，而不是“同时生成很多 token”。

  参考：
  - [Efficiently Scaling Transformer Inference](https://arxiv.org/abs/2211.05102) 里 §2 详细讨论了 decode 阶段为什么是 memory-bound。
:::

::: qa
question: “并行评分 $K$ 个 token 的延迟和 1 个几乎相同”，但 GPU 运算压力不是变成 $K$ 倍了吗？
section_id: m0-problem
answer: |
  运算量确实会增加，但 wall-clock 时间不一定增加，因为 decode 阶段小 batch 推理的瓶颈不是 FLOPs，而是**内存带宽**和**通信**。

  看一个简单估算：
  - 假设权重矩阵大小是 $d \times d$，一次 forward 要读 $d^2$ 个参数。
  - 算 1 个 token 时，激活向量是 $1 \times d$；算 $K$ 个 token 时，激活矩阵是 $K \times d$。
  - 权重读取量：还是 $d^2$（同一套权重）。
  - 激活读取/写入量：从 $d$ 变成 $K \cdot d$，但通常 $K \ll d$，占比不大。
  - 实际 FLOPs：从 $O(d^2)$ 变成 $O(K \cdot d^2)$，增加了 $K$ 倍。

  问题在：GPU 的算力（FLOPs/s）远远高于内存带宽（GB/s）。如果一次计算中读数据的时间占了 90%，那多算 $K$ 倍的数据并不会让总时间变成 $K$ 倍，只是让 GPU 计算单元从“等数据”变成“稍微忙一点”。

  具体到 Transformer decode：
  1. **Linear 层**：小 batch 下是 memory-bound。权重读取占主导，多 $K$ 个 token 激活变宽，但权重只读一遍。
  2. **Attention**：KV cache 已经存好了前面所有 token 的 key/value。验证 $K$ 个 token 时，只需要把它们的 query 和已有 KV 做 attention，KV 不用重新算。
  3. **分布式 all-reduce**：通信量主要和模型分片/张量大小有关，和一次验证几个 token 关系不大。

  所以结论不是“运算压力没变”，而是“运算压力增加了，但原本就没用满，真正卡住的环节几乎没变”。

  参考：
  - Chen et al., *Accelerating Large Language Model Decoding with Speculative Sampling*, §2.1 和 §3.1 讨论了小 batch decode 的瓶颈。
  - [Efficiently Scaling Transformer Inference](https://arxiv.org/abs/2211.05102) 图 1 显示了 decode 阶段大部分时间花在读取权重和 KV cache 上。
:::

延伸阅读：
- [Efficiently Scaling Transformer Inference](https://arxiv.org/abs/2211.05102)

## [m0-speculative-decoding] Speculative Decoding：Google Research 的视角

::: evidence
claim: Fast Inference from Transformers via Speculative Decoding 由 Leviathan, Kalman, Matias（Google Research）于 2022 年 11 月提交 arXiv，是“speculative decoding”这一术语的来源。
source: [speculative_decoding.pdf](raw/speculative_decoding.pdf)
status: verified
basis: 论文标题页明确标注作者单位为 Google Research，arXiv 日期为 2022-11-30。
:::

::: concept
title: 核心观察：难任务里常有容易子任务
why: 大模型不擅长的长程依赖，小模型可能在局部生成上猜得很准。

论文的出发点很直观：很多语言建模任务里，**大部分 next-token 预测其实不难**。比如：

- 标点、停用词、常见词组
- 代码里的模板结构
- 翻译里的固定搭配

这些“容易子任务”可以被一个更小的近似模型 $M_q$ 很好地近似，而大模型 $M_p$ 只需要验证这些猜测。如果小模型猜得准，就能一次推进多个 token；如果猜得不准，也保证不会破坏大模型的输出分布。
:::

::: concept
title: 拒绝采样规则与 bonus token
why: 这是投机解码“无损”的数学基础，也是工程实现的核心。

论文 Algorithm 1 给出了一轮投机解码的完整流程：

1. 用近似模型 $M_q$ 自回归地生成 $\gamma$ 个候选 token：$x_1, \dots, x_\gamma$。
2. 用目标模型 $M_p$ 并行计算 $\gamma + 1$ 个位置的概率分布：$p_1, \dots, p_{\gamma+1}$。
3. 对每个位置 $i$，采样 $r_i \sim U(0,1)$，找到第一个满足 $r_i > p_i(x_i) / q_i(x_i)$ 的位置 $n+1$；如果全部接受，则 $n = \gamma$。
4. 返回 $n$ 个接受的 token，再加上一个从修正分布中采样的 token：
   - 如果 $n = \gamma$：从 $p_{\gamma+1}$ 直接采样 bonus token。
   - 如果 $n < \gamma$：从 $\text{norm}(\max(0, p_{n+1} - q_{n+1}))$ 采样修正 token。

这样每轮至少产出 1 个 token（保证不比自回归慢），最多产出 $\gamma + 1$ 个 token。

延伸阅读：
- [speculative_decoding.pdf, §2.3 & Algorithm 1](raw/speculative_decoding.pdf)
:::

::: qa
question: Algorithm 1 里的接受/拒绝规则 $r_i > p_i(x_i)/q_i(x_i)$ 到底在做什么？bonus token 和修正 token 有什么区别？
section_id: m0-speculative-decoding
answer: |
  **先回忆拒绝采样的基本思想**

  假设你有一个很难采样的目标分布 $p$，但有一个容易采样的近似分布 $q$。拒绝采样的做法是：
  1. 从 $q$ 采样一个候选 $x$。
  2. 计算接受概率 $\min(1, p(x)/q(x))$。
  3. 以这个概率接受 $x$；否则重新采样。

  这样得到的样本服从 $p$。

  **投机解码为什么能一次处理一串？**

  因为这里的“候选”不是单个 token，而是 draft 模型自回归生成的 $\gamma$ 个 token：$x_1, x_2, \dots, x_\gamma$。目标模型并行计算这 $\gamma$ 个位置（外加第 $\gamma+1$ 个）的分布 $p_1, p_2, \dots, p_{\gamma+1}$。

  对每个位置 $i$，从 $q_i$ 得到候选 $x_i$，从目标模型得到 $p_i$。然后：
  - 采样 $r_i \sim U(0,1)$。
  - 如果 $r_i \le p_i(x_i)/q_i(x_i)$，接受 $x_i$。
  - 如果 $r_i > p_i(x_i)/q_i(x_i)$，拒绝 $x_i$，并**停止检查后面的候选**。

  为什么停止？因为 $x_{i+1}$ 的输入里包含 $x_i$。如果 $x_i$ 本身不是来自目标分布的有效样本，$x_{i+1}$ 就是建立在错误前缀上的，没有意义。

  **bonus token vs 修正 token**

  情况 1：前 $\gamma$ 个候选全部接受（$n = \gamma$）。
  - 目标模型已经多算了位置 $\gamma+1$ 的分布 $p_{\gamma+1}$。
  - 直接从 $p_{\gamma+1}$ 采样 1 个 token，作为“奖励”。
  - 本轮总产出：$\gamma$ 个接受候选 + 1 个 bonus = $\gamma + 1$ 个 token。

  情况 2：第 $n+1$ 个候选被拒绝（$n < \gamma$）。
  - 前 $n$ 个接受，后面的作废。
  - 需要从位置 $n+1$ 重新采样一个 token，但要补偿 draft 已经“预支”的概率质量。
  - 修正分布是 $\text{norm}((p_{n+1} - q_{n+1})_+)$。
  - 本轮总产出：$n$ 个接受候选 + 1 个修正 token。

  关键性质：即使 $n=0$（第一个候选就被拒绝），本轮也能产出 1 个 token，所以**不会比自回归慢**。

  参考：
  - Leviathan et al., *Fast Inference from Transformers via Speculative Decoding*, Algorithm 1 和 §2.3。
  - 论文 Appendix A.1 给出了接受/拒绝规则保持输出分布不变的形式化证明。
:::

::: evidence
claim: 在 T5-XXL 上，Speculative Decoding 实现了 2X–3X 的 walltime 加速，且输出与标准 T5X 完全一致。
source: [speculative_decoding.pdf](raw/speculative_decoding.pdf)
status: verified

## [m0-speculative-sampling] Speculative Sampling：DeepMind 的视角

::: evidence
claim: Accelerating Large Language Model Decoding with Speculative Sampling 由 Charlie Chen 等（DeepMind）于 2023 年 2 月提交 arXiv，用 Chinchilla 70B 展示了 2–2.5× 加速。
source: [speculative_sampling.pdf](raw/speculative_sampling.pdf)
status: verified
basis: 论文标题页标注所有作者来自 DeepMind，摘要报告了 Chinchilla 70B 在分布式设置下 2–2.5× 加速。
:::

::: concept
title: Modified rejection sampling：从单 token 到完整分布
why: 用修正后的拒绝采样直接证明目标分布可以被恢复。

Speculative Sampling 的算法流程与 Speculative Decoding 几乎相同，但论文花了大量篇幅在 **Theorem 1** 上证明修正拒绝采样的正确性：

给定目标分布 $q$ 和 draft 分布 $p$，采样 $\tilde{x} \sim p$，然后：

- 以概率 $\min(1, q(\tilde{x}) / p(\tilde{x}))$ 接受 $\tilde{x}$。
- 如果拒绝，从 $(q(x) - p(x))_+$ 中重采样。

论文证明最终样本 $X$ 满足 $P(X = x) = q(x)$，即**精确恢复了目标分布**。

这个证明的关键一步是计算拒绝概率：

$$
P(\tilde{x}\ \text{rejected}) = \sum_{x'} \max(0, q(x') - p(x'))
$$

它恰好是修正分布 $(q - p)_+$ 的归一化常数，所以两项相加后正好等于 $q(x)$。

延伸阅读：
- [speculative_sampling.pdf, §Algorithm 2 & Theorem 1](raw/speculative_sampling.pdf)
:::

::: qa
question: 为什么拒绝后要从 $(q - p)_+$ 重采样？采样完然后呢？
section_id: m0-speculative-sampling
answer: |
  **直觉：不能简单地从 $q$ 重新采样**

  假设候选 $\tilde{x}$ 被拒绝了，这意味着 $q(\tilde{x}) < p(\tilde{x})$：draft 模型 $p$ 在这个 token 上过度自信了。如果你现在直接从目标分布 $q$ 重采样，有可能再次采样到 $\tilde{x}$，而它的“一次机会”已经用过了。

  拒绝采样的核心要求是每个 token 的概率质量被正确计算。$p$ 已经给 $\tilde{x}$ 分配了 $p(\tilde{x})$ 的概率，但 $q$ 只想要 $q(\tilde{x})$。多出来的 $p(\tilde{x}) - q(\tilde{x})$ 这部分“错误质量”需要被补偿掉。

  所以修正采样只从 $q$ 比 $p$ 更看好的区域选：

  $$
  (q(x) - p(x))_+ = \max(0, q(x) - p(x))
  $$

  **采样完然后呢？**

  本轮输出就是这个重采样的 token，然后下一轮再重新生成 $\gamma$ 个候选。一旦拒绝，原来剩下的候选全部作废，不会继续验证。

  注意：这和 Speculative Decoding 的 bonus token 机制不同。Speculative Decoding 是在全部接受时“多赚”一个 token；Speculative Sampling 是在拒绝时“修正”一个 token。

  参考：
  - Chen et al., *Accelerating Large Language Model Decoding with Speculative Sampling*, §3.2 和 Theorem 1。
:::

::: qa
question: Theorem 1 的证明关键一步是什么？为什么最后能恢复目标分布 $q$？
section_id: m0-speculative-sampling
answer: |
  **目标**：证明通过 Speculative Sampling 得到的样本 $X$ 满足 $P(X = x) = q(x)$。

  **两种情况相加**

  情况 1：候选 $\tilde{x} = x$ 且被接受。
  $$
  P(\tilde{x}=x \text{ 且 accepted}) = p(x) \cdot \min\!\left(1, \frac{q(x)}{p(x)}\right) = \min(p(x), q(x))
  $$

  情况 2：候选被拒绝，然后从 $(q-p)_+$ 重采样得到 $x$。

  首先，候选被拒绝的总概率是：
  $$
  P(\text{rejected}) = \sum_{x'} p(x') \left(1 - \min\!\left(1, \frac{q(x')}{p(x')}\right)\right) = \sum_{x'} \max(0, p(x') - q(x'))
  $$

  然后，在已知被拒绝的条件下，从修正分布重采样得到 $x$ 的概率是：
  $$
  \frac{\max(0, q(x) - p(x))}{\sum_{x'} \max(0, q(x') - p(x'))}
  $$

  注意分母 $\sum_{x'} \max(0, q(x') - p(x'))$ 正好等于 $P(\text{rejected})$（因为 $\sum p = \sum q = 1$，可以验证这两个求和相等）。所以情况 2 的概率就是：
  $$
  \max(0, q(x) - p(x))
  $$

  **相加**：
  $$
  P(X=x) = \min(p(x), q(x)) + \max(0, q(x) - p(x)) = q(x)
  $$

  因此样本严格服从目标分布 $q$。

  参考：
  - Chen et al., *Accelerating Large Language Model Decoding with Speculative Sampling*, Theorem 1 及其证明。
:::

::: qa
question: 能走一遍修正拒绝采样的具体数值例子吗？
section_id: m0-speculative-sampling
answer: |
  假设词表只有 A、B、C 三个 token：

  | token | $q$（目标） | $p$（draft） |
  |---|---|---|
  | A | 0.5 | 0.3 |
  | B | 0.3 | 0.5 |
  | C | 0.2 | 0.2 |

  **第 1 步**：从 $p$ 采样候选。
  - 按 $p$ 分布，采样到 A 的概率 0.3，B 的概率 0.5，C 的概率 0.2。
  - 假设我们采样到了 **B**。

  **第 2 步**：决定是否接受 B。
  - 接受概率 = $\min(1, q(B)/p(B)) = \min(1, 0.3/0.5) = 0.6$。
  - 生成一个 $[0,1]$ 之间的随机数 $r$。
  - 如果 $r \le 0.6$，接受 B，输出 B。
  - 如果 $r > 0.6$，拒绝 B，进入第 3 步。

  **第 3 步**：拒绝后从 $(q-p)_+$ 重采样。
  - 对每个 token 计算 $\max(0, q - p)$：
    - A：$\max(0, 0.5 - 0.3) = 0.2$
    - B：$\max(0, 0.3 - 0.5) = 0$
    - C：$\max(0, 0.2 - 0.2) = 0$
  - 归一化：只有 A 有非零质量，所以采样到 A 的概率是 1。
  - 输出 **A**。

  **验证无偏性**

  现在我们直接按目标分布 $q$ 计算，输出 A 的概率应该是 0.5。

  通过 Speculative Sampling：
  - A 被直接接受：候选是 A，接受概率 $\min(1, 0.5/0.3)=1$，所以概率 $0.3 \times 1 = 0.3$。
  - A 通过修正采样得到：候选是 B 且被拒绝（概率 $0.5 \times 0.4 = 0.2$），然后修正采样得到 A（概率 1）。所以 $0.2 \times 1 = 0.2$。
  - A 通过修正采样得到：候选是 C 且被拒绝（概率 $0.2 \times 0 = 0$）， irrelevant。

  总概率：$0.3 + 0.2 = 0.5$，正好等于 $q(A)$。

  参考：
  - Chen et al., *Accelerating Large Language Model Decoding with Speculative Sampling*, Theorem 1 后的直观解释。
:::

::: concept
title: DeepMind 的 draft 设计：一个宽而浅的 4B 模型
why: 展示了一个具体的、可复现的 draft 训练方案。

Chen et al. 不是随便找一个小模型当 draft，而是为 Chinchilla 70B 专门训练了一个 draft 模型：

| | Target (Chinchilla) | Draft |
|---|---|---|
| $d_{\text{model}}$ | 8192 | 6144 |
| Heads | 64 | 48 |
| Layers | 80 | 8 |
| Params | 70B | 4B |

这个 draft 的关键设计是**宽而浅**：保持较大的 hidden dimension 以保留建模能力，但只有 8 层，从而最小化多设备通信开销。论文指出，语言模型对 aspect ratio 的变化相对鲁棒，所以这种设计可行。

- 数学风格 | 定义 α、β、DLK divergence，分析最优 γ | 用修正拒绝采样定理证明分布恢复
- 实验模型 | T5-XXL 11B、LaMDA 137B、GPT-like 97M | Chinchilla 70B
- Draft 来源 | 现成小模型（T5-small/base/large） | 专门训练的 4B 宽浅模型
- 关键算法元素 | Algorithm 1 + bonus token | Algorithm 2 + Theorem 1
:::

两篇论文的结论高度一致：**投机解码可以在不改变输出分布的前提下，把解码速度提升 2–3 倍**。

## [m0-limitations] 早期方法的局限

::: concept
title: 三个没有解决的问题
why: 这些局限直接催生了 Eagle、DFlash 和 DSpark。

1. **draft 模型怎么来？**
   Leviathan et al. 直接用现成小模型（如 T5-small）当 draft，接受率受限于小模型和目标任务的匹配度。Chen et al. 虽然训练了专门 draft，但需要额外训练成本。后来的方法（Eagle、Medusa、DSpark）开始研究**如何从目标模型自身结构蒸馏或外挂 draft 模块**。

2. **接受率不够高时加速有限**
   论文里的 α（单 token 接受率）通常在 0.5–0.9 之间。如果 draft 质量差，每轮只接受 1–2 个 token，draft 自身的开销可能吃掉大部分收益。这是后来研究 tree verification、并行 draft、半自回归 draft 的动力。

3. **验证开销与 batch 容量**
   两篇论文都主要分析单请求延迟。到了高并发 serving，所有请求的验证 token 会竞争 GPU batch 容量，验证策略直接影响系统吞吐。DSpark 的 confidence-scheduled verification 就是针对这个场景的改进。
:::

## [m0-timeline] 投机解码发展时间线

::: timeline
- 2018 | Stern et al. 提出 Blockwise Parallel Decoding，用多任务头并行解码，但输出分布会改变
- 2022.11 | Leviathan et al. 提出 Speculative Decoding，保证输出分布不变
- 2023.02 | Chen et al. 独立提出 Speculative Sampling，用 Chinchilla 70B 展示 2–2.5× 加速
- 2023–2024 | Eagle / Medusa 等自回归 draft 方法兴起，开始从目标模型训练 draft
- 2024 | DFlash 等并行 draft 方法出现，试图一次性生成更长候选块
- 2024 | DeepSeek MTP-1 把多 token 预测集成进生产基线
- 2025 | Eagle3 把自回归 draft 推向更浅更快的架构
- 2026 | DSpark 用半自回归 draft + 置信度调度验证，把并行 draft 推到生产
:::

## [m0-exercise] 练习：判断这些说法是否正确

::: exercise
判断以下说法是否正确，并说明理由。

1. 投机解码会改变目标模型的输出分布。
2. 如果 draft 模型很差，投机解码一定比自回归慢。
3. Speculative Decoding 和 Speculative Sampling 是两组完全独立的工作，核心思想完全不同。

--- answer
1. **错误**。两篇论文都通过拒绝采样或修正分布保证最终输出严格服从目标模型分布。Speculative Sampling 的 Theorem 1 和 Speculative Decoding 的 Appendix A.1 都给出了形式化证明。
2. **错误**。每轮至少能从修正分布中采样 1 个 bonus token，最坏情况与自回归相当。但 draft 计算会带来额外开销，实际可能略慢或持平，不会“一定更慢”。
3. **错误**。两篇论文几乎同时独立提出，核心思想高度一致：都是 cheap draft + parallel target verification + rejection sampling 来保证分布不变。差别在于术语、数学证明风格和实验设置。
---
:::

## [m0-summary] 本章小结

- 投机解码在 2022–2023 年由两组研究者几乎同时提出，核心都是 **cheap draft + target verify**。
- Speculative Decoding（Leviathan et al.） coined the term，给出了 Algorithm 1 和 bonus token 机制，实验覆盖 T5-XXL 和 LaMDA。
- Speculative Sampling（Chen et al.）用修正拒绝采样定理证明分布恢复，并在 Chinchilla 70B 上展示了 2–2.5× 加速。
- 两篇论文都保证输出分布与目标模型一致，但都没解决 draft 来源、接受率瓶颈和高并发 serving 的 batch 容量问题。
