# Answer

用户问的是：为什么 Transformer 把单次 forward 的并行度做到极致？

Transformer 的“单次 forward 并行度”主要指 **encode 阶段可以一次性处理整个输入序列**，每个 token 的表示可以通过自注意力（self-attention）和前馈层（FFN）并行计算，不需要像 RNN 那样逐时间步展开。RNN/LSTM 在训练和推理时都受到序列依赖的限制：第 $t$ 步必须等第 $t-1$ 步算完；而 Transformer 把序列长度这一维度展开成可并行的矩阵/张量运算，所以能充分利用 GPU/TPU 的 SIMD 算力。

但是到了 **decode/generation 阶段**，问题变成了：生成第 $t$ 个 token 时，必须已经知道第 $t-1$ 个 token。这个依赖是任务本身带来的（因果语言建模），不是模型结构能消除的。所以即使 Transformer 单次 forward 内部可以并行很多操作，**生成过程整体仍然被迫串行**。

总结：
- 单次 forward 内部并行度高 → Transformer 结构优势。
- decode 阶段串行 → 由自回归生成的因果约束决定。
