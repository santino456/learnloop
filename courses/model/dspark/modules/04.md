## [m4-deepspec] DeepSpec 仓库

::: concept
title: DeepSpec 是一个全栈训练与评估代码库
why: DSpark 不仅开源了权重，还开源了训练 draft 模型的完整流程。

DeepSpec 仓库（`deepseek-ai/DeepSpec`）包含三种投机解码算法实现、训练脚本、配置和 9 个离线 benchmark。
:::

| 组件 | 内容 | 用途 |
|------|------|------|
| 算法实现 | DSpark、DFlash、Eagle3 | 对比与复现投机解码方法 |
| 训练脚本 | 数据准备、多 GPU 训练、评估 | 从头训练或继续训练 draft 模块 |
| 配置文件 | `config/dspark/dspark_qwen3_4b.py` 等 | 定义模型、训练超参与数据路径 |
| 离线 benchmark | GSM8K、MATH、AIME25、HumanEval、MBPP、LiveCodeBench、MT-Bench、Alpaca、Arena-Hard-v2 | 评估 accepted length 与生成质量 |

::: concept
title: 冻结目标模型，复用 embedding 与输出头
why: 不需要重新训练大模型，只需要训练一个外挂 draft 模块。

DSpark 的训练只更新 draft 模块参数：

- 目标模型（如 DeepSeek-V4）权重完全冻结。
- Draft backbone、sequential head、confidence head 从零或 warmup 开始训练。
- Embedding 层和输出头复用目标模型，保证 draft 与 target 的 token 分布对齐。

这样做的好处是训练成本低，且不会破坏原模型的输出分布。
:::

## [m4-data-prep] 训练数据准备

::: concept
title: Open-PerfectBlend 与响应再生
why: 训练分布需要与目标模型对齐，使用目标模型自己生成的响应比原始数据更稳定。

论文使用 Open-PerfectBlend 2 作为训练数据源，它是 PerfectBlend 的开源版本，共约 130 万条指令数据，领域分布如下：

| 领域 | 占比 |
|---|---|
| 数学 | 39.4% |
| 代码 | 38.9% |
| 聊天 | 17.6% |
| 指令遵循 | 4.1% |

训练时**只使用数据集中的 prompt**，而对应的 response 则由每个目标模型重新生成。这样能保证：
- draft 模型学习的是目标模型自己的输出分布，而不是原始数据集中可能由其他模型生成的分布；
- 不同目标模型（Qwen3-4B/8B/14B、Gemma4-12B）可以共用同一批 prompt，但各自生成适配自己的训练数据。

每个 drafter 训练 10 个 epoch 以确保收敛。训练与评估均采用非思考模式（non-thinking mode）。

参考：DSpark 论文 §4.1 / p10。
:::

::: evidence
claim: DSpark 使用 Open-PerfectBlend 2 的 130 万条 prompt，响应由每个目标模型重新生成，训练 10 个 epoch。
source: [DSpark 论文 PDF](https://github.com/deepseek-ai/DeepSpec/blob/main/DSpark_paper.pdf)
status: verified
basis: 论文 §4.1 / p10 明确说明数据来源、领域占比、响应再生策略与训练轮数。
:::

## [m4-loss] 训练目标详解

::: concept
title: 三项损失与默认权重
why: 同时优化 draft 质量、分布对齐度和置信度准确度。

DSpark 的总损失是三项的加权和：

$$
\mathcal{L} = \alpha_{\text{ce}} \mathcal{L}_{\text{ce}} + \alpha_{\text{tv}} \mathcal{L}_{\text{tv}} + \alpha_{\text{conf}} \mathcal{L}_{\text{conf}}
$$

| 损失项 | 含义 | 作用 | 默认权重 |
|---|---|---|---|
| $\mathcal{L}_{\text{ce}}$ | 标准交叉熵 | 让 draft 模型在 anchor 条件下给出合理的 next-token 分布 | 0.1 |
| $\mathcal{L}_{\text{tv}}$ | 总变差 | 最小化 draft 分布 $p^d$ 与目标分布 $p^t$ 之间的 $\ell_1$ 距离 | 0.9 |
| $\mathcal{L}_{\text{conf}}$ | 置信度 | 让 confidence head 输出接近真实接受率 $c_k^* = 1 - \frac{1}{2}\|p_k^d - p_k^t\|_1$ | 1.0 |

总变差损失的权重（0.9）远高于交叉熵（0.1），说明 DSpark 更关心 draft 分布与目标分布的对齐程度，而不是 draft 单独的语言建模困惑度。confidence 损失权重最高（1.0），因为 confidence head 的准确度直接影响调度器决策。

参考：DSpark 论文 §3.3 / p10，公式 (12)。
:::

::: qa
question: 为什么交叉熵权重只有 0.1，而总变差权重是 0.9？
section_id: m4-loss
answer: |
  因为投机解码的核心目标是让 draft 分布尽可能接近目标分布，而不是让 draft 模型单独成为一个好的语言模型。

  标准交叉熵损失训练的是“给定前缀，预测下一个 token”的能力。它能让 draft 模型生成流畅文本，但不能保证这些 token 会被目标模型接受。如果 draft 分布与目标分布差异大，即使 draft 的困惑度很低，接受率也会很差。

  总变差损失直接优化 $\|p^d - p^t\|_1$，也就是两个分布的 $\ell_1$ 距离。根据公式 (8)，$c_k^* = 1 - \frac{1}{2}\|p_k^d - p_k^t\|_1$，所以总变差越小，真实接受率越高。这是投机解码 speedup 的直接决定因素。

  把 $\mathcal{L}_{\text{tv}}$ 权重设为 0.9、$\mathcal{L}_{\text{ce}}$ 设为 0.1，相当于告诉模型：你可以不完全像自回归语言模型那样优化困惑度，但必须让 draft 分布与目标分布尽量重合。

  参考：DSpark 论文 §3.3 / p10。
:::

## [m4-system-optimizations] 系统级训练优化

::: concept
title: Hidden State 通信替代全词表 Logits
why: 跨 worker 传输全词表 logit 的带宽开销太大，传 hidden state 可以把复杂度从 $O(V)$ 降到 $O(d)$。

训练 draft 模型需要目标模型的输出分布作为监督信号。最直接的做法是让目标模型输出每个 token 的全词表 logits（$V \approx 10^5$），然后传给 draft 模型的 worker。但这会造成严重带宽瓶颈。

论文采用的优化是：
1. 目标模型 forward 时缓存其激活；
2. worker 间只传输 LM head **之前一层**的 hidden state，维度为 $d$（通常几千）；
3. LM head 投影在 draft 模型所在的 worker 上本地执行，且只对采样出的目标位置计算。

这样 per-token 通信复杂度从 $O(V)$ 降到 $O(d)$，大幅减少了多机训练时的通信量。

参考：DSpark 论文 §5.1 / p16。
:::

::: concept
title: Anchor-Bounded Sequence Packing
why: 把 draft 模型的计算成本与目标模型的上下文长度解耦。

长训练序列如果直接送给 draft 模型，attention 和 FFN 成本都会随序列长度增长。论文采用 anchor-bounded sequence packing：
- 从一条训练序列中采样固定数量的 draft anchor 位置；
- 每个 anchor 只带其后面的 $\gamma$ 个 token 组成一个训练块；
- 把这些块打包进一个 batch，而不是让 draft 模型处理整条序列。

这样无论原始序列多长，draft 模型每次处理的序列长度都是 $O(\gamma)$ 级别，计算成本稳定可控。

参考：DSpark 论文 §5.1 / p16。
:::

## [m4-training-command] 端到端训练命令与配置解读

::: concept
title: 典型训练流程
why: 把数据准备、target cache、draft 训练、评估串成一个可复现的流水线。

一个完整的 DSpark 训练流程通常分为四步：

| 阶段 | 主要工作 | 输入 | 输出 | 主要成本 |
|------|----------|------|------|----------|
| 数据准备 | 收集并切分训练语料 | 原始文本 / 对话数据 | 训练序列 | 数据清洗与存储 |
| Target cache | 用冻结目标模型前向训练数据 | 训练序列 | 中间层特征与输出分布 | 大量存储空间（Qwen3-4B 约 38 TB） |
| Draft 训练 | 训练 backbone、sequential head、confidence head | Target cache + 训练序列 | DSpark checkpoint | 8 GPU 训练时间 |
| 评估 | 在 9 个 benchmark 上测 accepted length | 训练好的 checkpoint | 评估报告 | 推理算力 |

参考：DSpark 论文 §5.1 / p16；38 TB target cache 数据来自相关技术报道。
:::

::: evidence
claim: DSpark 的训练配置默认单节点 8 GPU，Qwen3-4B 设置下 target cache 约 38 TB。
source: [MarkTechPost: DeepSeek Releases DSpark](https://www.marktechpost.com/2026/06/27/deepseek-releases-dspark-a-speculative-decoding-framework-that-accelerates-deepseek-v4-per-user-generation-60-85-over-mtp-1/)
status: verified
basis: 报道明确提到默认 8 GPU 配置与约 38 TB target cache（Qwen3-4B 设置）。
:::

::: concept
title: 训练命令与配置解读（示例）

以下是一个代表性的训练命令，具体参数名需以 DeepSpec 仓库最新版本为准：

```bash
# 1. 生成 target cache（由目标模型自己生成响应并缓存 hidden state）
python -m deepspec.data.prepare \
  --dataset open-perfectblend \
  --target_model Qwen3-4B \
  --output_dir ./cache/qwen3_4b_target \
  --max_seq_len 8192 \
  --num_workers 8

# 2. 训练 DSpark draft 模块
python -m deepspec.train \
  --config config/dspark/dspark_qwen3_4b.py \
  --target_cache ./cache/qwen3_4b_target \
  --output_dir ./checkpoints/dspark_qwen3_4b \
  --num_gpus 8
```

配置 `config/dspark/dspark_qwen3_4b.py` 中通常包含以下关键字段：

| 配置项 | 示例值 | 含义 |
|---|---|---|
| `target_model` | `"Qwen3-4B"` | 冻结的目标模型 |
| `draft_layers` | `5` | draft backbone 层数 |
| `block_size` | `7` | 最大候选块长 $\gamma$ |
| `markov_rank` | `256` | Markov head 低秩 $r$ |
| `feature_layers` | `[8, 16, 24]` | 从目标模型哪些层抽取 KV 注入特征 |
| `alpha_ce / alpha_tv / alpha_conf` | `0.1 / 0.9 / 1.0` | 三项损失权重 |
| `epochs` | `10` | 训练轮数 |

这些配置直接对应论文中的设计选择：5 层 draft backbone、$\gamma=7$、Markov rank $r=256$、默认损失权重。

参考：DSpark 论文 §4.1 / p10 与 §5.1 / p16；命令为根据 DeepSpec 常见模式整理的示例，部署前请核对仓库最新文档。
:::

::: evidence
claim: DSpark 的 draft backbone 默认 5 层，最大块长 $\gamma$ 在离线实验中为 7，生产部署中为 5。
source: [DSpark 论文 PDF](https://github.com/deepseek-ai/DeepSpec/blob/main/DSpark_paper.pdf)
status: verified
basis: 论文 §4.1 / p10 说明离线实验 block size 为 7；§5.1 / p16 说明生产部署 DeepSeek-V4-Flash/Pro 使用 $\gamma=5$。
:::

## [m4-summary] 本章小结

- DeepSpec 提供 DSpark / DFlash / Eagle3 的全栈训练与评估代码。
- 训练数据使用 Open-PerfectBlend 2 的 prompt，响应由目标模型重新生成，训练 10 个 epoch。
- 总损失 $\mathcal{L} = 0.1\mathcal{L}_{\text{ce}} + 0.9\mathcal{L}_{\text{tv}} + 1.0\mathcal{L}_{\text{conf}}$，重点优化 draft 与目标分布的对齐度。
- Hidden state 通信把跨 worker 传输复杂度从 $O(V)$ 降到 $O(d)$；anchor-bounded packing 把 draft 成本与目标上下文长度解耦。
- DSpark 冻结目标模型，只训练 draft 模块，5 层 backbone、离线 $\gamma=7$、生产 $\gamma=5$。
- vLLM、SGLang 等引擎正在集成，部署前需核对最新文档。
